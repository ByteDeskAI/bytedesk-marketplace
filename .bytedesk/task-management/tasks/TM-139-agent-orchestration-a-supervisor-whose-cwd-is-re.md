Found immediately after merging ebc92e3, by the very logging that merge added — every supervisor record under ~/.local/state/bytedesk/agent-orchestration/supervision/ shows state 'starting', restarts 0, a dead pid, and a log containing: Error: ENOENT: no such file or directory, uv_cwd, at absolutize (topology/lib/util.mjs:120) from context (topology/cli.mjs:114) from supervise. Root cause: absolutize(path, base = process.cwd()) evaluates its DEFAULT PARAMETER on every call, so process.cwd() runs even when path is already absolute and base is never used. context() then calls it with an explicit, absolute --consumer, needing no cwd at all — and still dies. This is not merely a test artifact: tm removes a task-owned worktree after a verified merge, which is a documented routine cleanup step, so any supervisor started with that worktree as its cwd dies the same way. It died silently before, because the spawn used stdio:'ignore'.
