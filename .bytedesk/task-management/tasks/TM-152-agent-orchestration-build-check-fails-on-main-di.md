`npm run build:check` (scripts/check-bundle.mjs) exits non-zero on unmodified main with "Tracked bundle is stale: dist/claude-agent-acp.mjs". Reproduced with a genuine control: a `git archive main` extract, using the SAME node_modules as the working tree so esbuild is held constant, fails identically. So it is not caused by any branch in flight — TM-143's diff touches topology/lib/mailbox.mjs and no ACP source at all, and fails the same way.

This matters because build:check is a gate every EP-018 task has been reporting as passing. It ran green during TM-135 (base 36b9308) and fails at main 9c765c3, so the staleness entered somewhere between those two revisions, or the bundle was always stale and an earlier run compared it against a different esbuild.

The tracked bundle was last rebuilt at 9e30405 (agent-orchestration 0.2.3), which is old. The likely fix is simply `npm run build` and committing the regenerated dist, but the cause must be established first: a bundle that silently drifts from its sources is worse than a stale one, because check-bundle.mjs is the only thing that would tell anyone.
