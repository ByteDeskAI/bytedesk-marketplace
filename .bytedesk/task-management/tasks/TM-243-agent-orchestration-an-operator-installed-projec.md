Requested 2026-09-25 by Ryan via gateway lead d60f0608 ('ship it with the plugin, not works-on-my-machine'). Claude Code's auto-mode classifier denies a lead running 'ao-topology manage record-landing --authorized' as Self-Approval / Self-Modification, so every landing needs Ryan; gateway landings (TM-467, TM-464) are going unrecorded meanwhile. Per the gateway lead's reading of the Claude Code docs (not re-verified here): a plugin PreToolUse 'allow' does not override the classifier, plugins cannot ship permission rules, and plugin MCP tools also pass through the classifier; only settings allow rules (user, project, managed) do. Proposed shape: (1) an operator-run, once-per-repo 'ao-topology permissions install' (or part of lead ensure) shows a diff and writes project-scope .claude/settings.json allow rules for the governed lead verbs only, committed like the existing marketplace block; uninstall removes them. (2) those verbs work as bare commands, resolving the caller from the managed session's own binding, because env-var prefixes break rule matching. (3) Authority stays with TM-234: the rule only removes the prompt; record-landing and integrate still refuse without a valid, unexpired operator delegation covering caller, repo and scope. Filed as --human: it widens what runs without a prompt in every consuming repo, so the operator confirms the rule list and the install step before a worker takes it.
