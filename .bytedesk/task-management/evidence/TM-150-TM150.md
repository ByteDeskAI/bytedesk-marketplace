# TM-150 — the deny rule that matched nothing, and the flags that actually enforce

Committed at `26927d6`.

## What was wrong

`MultiEdit` is no longer a tool the CLI exposes, so a rule naming it produces
`Permission deny rule 'MultiEdit' matches no known tool` and denies nothing. It appeared in two
places, not the one originally reported:

- `providers/claude.json` → `coordinator_args`
- `topology/lib/reviewer.mjs` → the reviewer isolation argv

Both cleaned. The tools the CLI *does* know are still denied.

## The finding that outlives the fix

The deny list is **not** what makes the reviewer read-only. Measured with three bounded runs:

| argv | result |
|---|---|
| `--disallowed-tools Write,Edit` | refused to Write — **then created the file with Bash** |
| the same plus an unmatched name | warned about the name, Write still denied, file still created |
| the reviewer's real argv (`--restricted --safe-mode …`) | "no file-writing tool is available to me (no Write/Edit/Bash…)" — no file |

The list removes named tools; it does not remove the shell. `--restricted`/`--safe-mode` remove Bash
entirely, and that is the whole of the isolation.

So the part that **looks** like the enforcement is advisory, and the two flags nobody reads are
load-bearing. Anyone "simplifying" `buildReviewerArgv` by dropping them and trusting the deny list
plus `TOPOLOGY_REVIEWER_READ_ONLY` would break isolation **silently** — every test green, the
invariant still passing. That is what the file's own "never a silent downgrade" note fears, arriving
through the door that note is not watching.

That reasoning now sits beside the argv instead of in a task comment, which is the point: the next
person to touch this line reads it there.

## Evidence

A regression test asserts three things: no deny rule names an unknown tool in either site, the known
ones are still denied, and `--restricted` and `--safe-mode` are still present.

Non-vacuity: over unmodified `HEAD`, in a real checkout, it is the only failure — 7 pass, 1 fail.

Gates: topology 380/380, unit 557 tests / 553 pass / 4 skipped, `build:check` 0, `roadmap:check` 0,
frozen v1 validators 0, v2 check 0.

## Not claimed

The three bounded runs above were made by the worktree author when this was diagnosed; this session
removed the stale name, wrote the reasoning into the code, and added the regression test. No live
reviewer was re-driven here — the behaviour asserted is the argv's contents, not the CLI's response
to it.
