# TM-138 — producer populates the additive header keys

Committed at `bb3e084`.

## AC1 was ticked and false

It claims `collectPresenceAgents` populates six keys. Checked in the tree rather than in the record:
only `roleName` was implemented. `activity`, `mailboxDepth`, `task`, `slots` and top-level
`slotQueues` appeared **only** in the addendum, the fixtures and the countersignature request —
never in producer code. The entry object built by `add()` carried none of them.

Un-ticked and recorded before any work started, because that tick had stood across several sessions
and anyone reading the board would have concluded the producer work was finished.

## What each key now reads from

| key | source |
|---|---|
| `activity` | the census document, with `observedAt` from its own top-level `at` |
| `mailboxDepth` | `queueDepth` across the run directories |
| `task` | the management record's unreleased `assignee` |
| `slots` | held, plus waiting with 1-based position |
| `slotQueues` | top-level: name, holder, heldSince, waiting |
| `roleName` | unchanged, with the unknown-role mapping it depends on |

## The load-bearing decision: every source is read READ-ONLY

The obvious readers are the wrong ones. `slotStatus()` takes a lock per slot and **commits** a
reconciled record; `managementStatus()` builds a context and a task-store binding. Either one called
from here would turn a publisher — whose own first line says "read-only metadata, never authority" —
into something that mutates the state it publishes, on every heartbeat, roughly every ten seconds,
forever.

The records are read directly instead. **A publisher must never write what it reports.**

## Two honesty properties, both deliberate

- **A stale census contributes nothing.** `withStaleness` already rewrites those agents to
  `unknown`; publishing `unknown` as though it were observed is exactly the confidently-wrong
  verdict the addendum forbids, and it is the same failure D1 was raised about.
- **A key is absent when unknown, never a placeholder.** A `null` task or an empty `slots` invites a
  consumer to conclude something was measured and found empty. That is not what happened.
