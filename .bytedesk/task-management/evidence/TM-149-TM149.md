# TM-149 — the handshake test skips where it cannot be answered

Committed at `5326ea9`.

## Why it failed by construction

`serverVersion()` tries three sources in order:

1. a manifest `version` — **absent by design**, because these plugins are versionless so every
   commit reaches consumers by SHA;
2. a SHA in the installed directory name;
3. `git describe`.

A `git archive` extract has none of the three, so `dev` is the **correct** answer there — and a test
asserting `!== "dev"` fails at every revision, forever, for a reason that has nothing to do with the
code under test.

## The fix

It skips when none of the three can answer, and the skip message names the cause **and** the
remedy: *run the gates from a checkout or a clone, not a `git archive` tree.* In a real checkout
nothing changes.

| where | before | after |
|---|---|---|
| archive tree | 1 fail | **1366 pass, 0 fail, 1 skip** |
| real checkout | asserting | **1370 pass, 0 fail, 0 skipped** — still asserting |

Both measured. AC2 is the one that keeps this honest: a checkout whose handshake genuinely answers
`dev` still fails, because the skip is gated on whether the environment *can* answer, not on the
answer itself.

## Why it was worth fixing rather than documenting

Gates were run from archive trees twice during EP-018 and this failure was reported as a real defect
both times — once as "the tracked bundle is stale", once as a blocker on another task. Both cost
real time to disprove.

The rule also caught its own author: the first non-vacuity check for TM-148, earlier in this same
session, ran in an archive tree and its *precondition* failed for exactly this reason — making a
test look non-vacuous for an environmental cause rather than for the absence of a fix. The comment
points at `.claude/rules/verification-that-can-fail.md` rule 2, where the general form lives:
**isolation is never free, and what `git archive` removes is `.git`.**

## Note on the implementation

Three imports are aliased because the file already imports `join`, `existsSync` and others further
down. Colliding with them is what the first two attempts did, and both failed loudly at
`node --check` rather than silently — which is the good case.
