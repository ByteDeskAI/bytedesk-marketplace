codex
The final checks reproduced three failures in memory: rollback leaves duplicate task IDs after a title change, a failed session close makes a committed approval replayable, and a task described as having “no epic” lands under an epic activated by the same proposal. The ACP error-coercion issue was fixed concurrently and is excluded from the report.
codex
- **HIGH — rollback corrupts renamed tasks.** [planner-ops.mjs:485](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/planner-ops.mjs:485) discards the snapshot’s original filename. Rename an existing task, apply `task.depends`, then fail a later operation: rollback creates a second file using the new title while leaving the original file modified. Reproduced in memory: duplicate IDs, original still blocked.

- **HIGH — a committed approval becomes replayable after a bookkeeping failure.** [dashboard-api.mjs:1071](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/dashboard-api.mjs:1071) catches `closeSession()` failures as though `applyOps()` rolled back. A successful apply followed by a transient session-write failure restores the proposal; retrying the identical digest creates everything again. Reproduced in memory.

- **HIGH — confirmation can silently switch proposals.** [GoalPlanner.tsx:176](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/dashboard/src/features/plans/GoalPlanner.tsx:176) replaces the proposal without clearing `reviewed` or closing confirmation. Review A while an agent runs; its completion loads B; clicking the already-enabled confirmation sends **B’s** digest at [line 259](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/dashboard/src/features/plans/GoalPlanner.tsx:259). B’s arguments were never reviewed.

- **HIGH — another localhost website can write without approval.** [tm-dashboard:283](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/bin/tm-dashboard:283) accepts every localhost port as the same origin. A page on another port can send a simple `text/plain` POST containing `{"title":"Unapproved"}` to `/api/epic`; JSON parsing accepts it and the endpoint creates and activates an epic. CORS need not permit reading the response.

- **HIGH — “no epic” remains an unfrozen destination.** [planner-ops.mjs:377](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/planner-ops.mjs:377) leaves missing destinations unresolved when no epic is active. With `requireEpic:false`, approve `[epic.create E, epic.activate E, task.create without epic]`: the card says “with no epic,” but [line 131](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/planner-ops.mjs:131) files the task under E. Reproduced in memory.

- **HIGH — process crashes defeat both atomic apply implementations.** [planner-ops.mjs:454](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/planner-ops.mjs:454) and [goal-import.mjs:207](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/goal-import.mjs:207) commit records individually with only exception-based compensation. Kill the process after epic activation and the first task: those changes survive permanently. Reopening `"applying"` sessions neither identifies nor reverses the partial transaction.

- **MEDIUM — proposing consumes board overrides.** [planner-ops.mjs:118](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/planner-ops.mjs:118) invokes the mutating gate during preview. With saturated WIP and an override pending, `tm_plan_propose` clears the override and logs its consumption before approval. Reproduced in memory. The “every permitted tool” test at [planner-bridge.test.mjs:412](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/tests/unit/planner-bridge.test.mjs:412) supplies no operations, so it never exercises this path.

- **MEDIUM — the gate fix still skips later refusals.** [planner-ops.mjs:122](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/planner-ops.mjs:122) suppresses “no active epic,” but that gate returned before checking completeness or WIP. Set `requireEpic:true`, no active epic, and saturated WIP; a proposal explicitly naming an existing epic still validates and creates tasks. Manifest creation at [goal-import.mjs:218](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/goal-import.mjs:218) bypasses those gates entirely.

- **MEDIUM — manifests still create dependency cycles.** [goal-import.mjs:251](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/goal-import.mjs:251) writes dependencies through raw mutations. A valid manifest containing `A → B → A`, or `A → A`, imports permanently blocked work despite the fixed `task.depends` refusal. Reproduced in memory.

- **MEDIUM — duplicate manifest IDs misdirect dependencies.** [goal-import.mjs:238](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/goal-import.mjs:238) overwrites earlier mappings. Two goals named `A` create two tasks, but the result reports only the second and resolves both goals’ dependency operations onto it. Reproduced in memory.

- **MEDIUM — initial goal paths bypass realpath confinement.** [dashboard-api.mjs:1232](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/dashboard-api.mjs:1232) checks only the lexical path. A repository symlink pointing to an external goal document passes; preview exposes its parsed content and import copies it into the board. The manifest’s referenced-document fix does not cover this entry path.

- **MEDIUM — framed stdout can still exhaust host memory.** [planner-run.mjs:99](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/lib/planner-run.mjs:99) caps event count, not bytes. Hundreds of valid, newline-terminated unknown updates just below 4 MiB become retained RAW events, consuming gigabytes before eviction. The unterminated-line fix does not prevent this.

- **MEDIUM — malformed attachment URLs terminate the dashboard.** [tm-dashboard:318](/home/ryan/Documents/GitHub/ByteDeskAI/bytedesk-marketplace/task-management/bin/tm-dashboard:318) calls `decodeURIComponent()` outside any exception handler. `GET /api/planner/%/attachment/<64-hex-hash>` throws `URIError` directly from the HTTP callback instead of returning a refusal.
