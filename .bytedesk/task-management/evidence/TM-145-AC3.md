# TM-145 AC3 / AC4 — the evidence surgery, executed in the mandated order

Census taken at execution time, not from the earlier table, because the population grew with every
attach while the fix was in flight. **18 doubled files.**

## What the census showed, and why the naive rule was wrong

| class | count | action taken |
|---|---|---|
| orphaned — no other copy exists | 4 | **renamed**, never deleted |
| byte-identical to a sibling | 12 | record **repointed first**, then the doubled file removed |
| content differs from its sibling | 2 | **left untouched** — two artifacts, not one duplicated |

The decisive fact: **every one of the 18 was referenced by a task record, and not one clean sibling
was referenced by anything.** Each task pointed only at its own prefixed copy. So there was no such
thing as a safely-deletable duplicate — "byte-identical therefore droppable" would have stripped the
only evidence ref from twelve tasks, and `doctor`'s `missing-evidence` repair (`doctor.mjs:279`,
which *drops* a ref whose file is gone) would then have removed those links permanently.

The safety test is reference topology, not content equality.

## A hazard the dry run caught

The first implementation repointed with a blanket regex over every doubled path. That would also
have repointed **TM-127 and TM-131** — the two whose doubled file holds *different content* from its
sibling — silently swapping each record onto an artifact it was not written about. Corrected to
repoint only orphaned and byte-identical pairs; the differing pair is excluded by name.

## Result

    renamed=4  repointed=15  removed=12  differs-left=2

| verification | result |
|---|---|
| doubled files remaining | **2** — exactly the differing pair |
| evidence refs checked across all tasks | **147** |
| dangling refs | **0** |
| `tm doctor` `missing-evidence` findings | **0** — nothing for `--fix` to strip |

## Left for a human decision, deliberately

Both are cases where two agents attached different content under near-identical names, so only a
byte comparison separates them:

- `TM-127-TM-127-INTEGRATION-VERIFICATION.md` (4,120 b) vs `TM-127-INTEGRATION-VERIFICATION.md`
  (7,241 b) — 63 differing lines. Referenced by TM-127 and by TM-145.
- `TM-131-TM-130-131-INTEGRATION-VERIFICATION.md` (5,118 b) vs `TM-130-131-INTEGRATION-VERIFICATION.md`
  (8,443 b) — 56 differing lines. Referenced by TM-131 and by TM-145.

In both cases the shorter, prefixed file is the one the task record points at, and the longer
sibling is unreferenced. Deciding which is authoritative — or whether both should be kept under
distinct names — is a content judgement about what each verification actually recorded, and it is
not one an integrator should make by rule.
