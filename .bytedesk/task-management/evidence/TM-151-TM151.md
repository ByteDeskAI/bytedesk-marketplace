# TM-151 AC1 — readiness decided by style, not by text

Committed at `6da2556`.

## Why the earlier fix could not finish the job

The merged partial fix added a literal `Try "` branch to the four `claude.json` fields. That covers
the fresh-session hint and nothing else. An idle agent renders `❯ init the task store`, which scores
zero against both the shipped pattern and the literal branch — which is why a healthy reviewer never
registered and no governed launch could start.

The reason is structural, not a missed case: **a composer holding Claude's dim suggestion and one
holding a human's typed draft are identical as text.** Both are ordinary letters after the glyph.
No pattern over a plain capture can separate them, and the half-typed-draft negative that makes the
literal branch safe is the same property that makes the general case unanswerable that way.

## What changed

`evaluateScreen` takes an optional styled screen and, **only after the pattern has already failed**,
asks `composerEmptyStyled` whether every visible character after the glyph is ghost text.

- **Reuses** the discriminator `delivery.mjs` already had rather than deriving a second answer to
  the same question. Deriving a second one is exactly the drift that produced the previous defect on
  this path, where the styled check reached the ring gate but not the landing verdict.
- **One-way by construction.** It can only turn "keep waiting" into "ready", never the reverse, and
  anything it cannot parse stays undecided. A pane mid-answer and a pane holding a draft both fail it.
- **Costs nothing when not needed.** The caller captures with `-e` only when the cheap plain test
  decided nothing.
- `lastComposerLine` takes the **last** glyph-bearing line, because an agent's own answer can quote
  a glyph and the box is redrawn at the bottom.

## Evidence

Two tests. The first was proven non-vacuous rather than assumed: applied over unmodified `HEAD`,
with the new symbol import removed so it fails on **behaviour** and not on a missing export, it is
the only failure — **49 pass, 1 fail**. It also asserts its own precondition, that the plain text of
both cases is identical in shape and neither matches the pattern, so it cannot pass for the wrong
reason.

## What is NOT claimed

**This has not been driven on a live pane by this session.** The mechanism it relies on — that
Claude renders suggestions with SGR 2 and drafts bright — was measured on live panes by the worktree
author when `composerEmptyStyled` was written, and those measurements are quoted in `delivery.mjs`.
Reusing a measured discriminator is a stronger position than inventing one, but it is still not the
same as watching a reviewer register, and AC3 of this task is about the pattern fields rather than
this path.
