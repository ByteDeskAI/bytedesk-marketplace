## Colour caveat

This product's accent is a mid-tone blue. The renderer reliably pulls that
family toward a saturated primary — `#4C7DFF` failed twice under maximal
specification — so the blue here reads more vivid than the token. Cyan, orange,
pink and amber land true; blues do not. **Do not read a colour value off this
image.** The token file is the authority.

## Concern — recorded, not resolved

This piece is the weakest in the set and is kept only because its round 2 was worse.

Round 1 renders four tracks carrying discrete markers, which read as a progress
diagram. Round 2 changed the form language to light travelling inside recessed
channels and produced something closer to the component still: four capsule
tracks with blue fills at roughly a third, two thirds and full, plus one empty —
a progress bar in all but name.

That crosses the design system's rule that generated art must not contain
interface elements. Two rounds converging on the same component says the brief is
wrong rather than the prompt: *parallel tracks at differing completion* is
inherently a progress-bar idea, so every rendering of it lands on the widget.

The fix is a different subject, not another round. Orchestration's real subject is
many agents under one hand — the direction that already worked for `bytedesk-ai`
(nine forms, one lit). A re-brief should move toward convergence and dispatch —
lines meeting at a point — and drop the completion metaphor entirely.

Until then, treat this image as a placeholder and do not cite it as direction.
