# Agent Memory - Design

## Product stance

Agent Memory is a living knowledge map with visible trust boundaries. Product
workbenches may be dense; the public site may breathe; both share the same brain
metaphor, scope grammar, and Black Glass family anatomy.

## Token source

Consume `.context/design-system/tokens/` and set
`data-bd-product="agent-memory"`. Use the canonical Agent Memory pink accent,
exact dark/light geometry, and `soft|balanced|rich` dark richness.

## Personality

- **Icon:** a dimensional brain whose lobes resolve into scoped memory nodes. It
  must read as memory first, not a generic sparkle, database, or network.
- **Density:** explanatory on the public site; compact and schema-forward in tools.
- **Depth:** ownership tiers form nested optical planes; selected memory evidence
  rises without turning every record into a card.
- **Motion:** calm recall, store, and boundary transitions; denials never shake or
  flash theatrically.
- **Voice and type:** technical and trustworthy, with Mono for addresses, schemas,
  policies, payloads, and telemetry.
- **Motif:** nested compartments connected by permissioned recall paths.

## Components and states

Required components include memory scope/address, ownership path, policy result,
recall/store evidence, model/schema selector, transport examples, storage state,
and trust-boundary diagrams. Cover empty, loading, recalled, stored, granted,
denied, partially available, unavailable, invalid model, and storage failure.

Storybook and HTML mockups cover the product workbench and every in-repository site
page, both themes, all richness levels, responsive widths, keyboard/focus, reduced
motion, and complete permission/error states before runtime adoption.

## Accessibility

Every ownership diagram has a text equivalent stating who may read and write.
Scope and policy results never rely on color. Long addresses remain readable at
200% zoom and all progressive disclosure is keyboard operable.

## Exceptions to the shared foundation

None.
