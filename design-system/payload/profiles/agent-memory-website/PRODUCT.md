# ByteDesk Agent Memory Website — Product Direction

## One-liner

Durable, permissioned, shared memory for organizations that run fleets of AI agents.

## Audience

- Teams operating MCP-capable agents that need shared knowledge without leaking
  private agent or department context.
- Platform engineers selecting a memory service, storage backend, or SDK.
- Security and operations reviewers validating the trust boundary before adoption.

## Reader outcomes

The website should help a reader understand:

1. how organization, department, agent, customer, and initiative memory is scoped;
2. where policy enforcement occurs and what a denied request looks like;
3. how REST, MCP, generated SDKs, schemas, and storage plugins fit together; and
4. how to evaluate or deploy the service inside a chosen trust boundary.

## Voice

Direct, technical, and evidence-led. Define specialized terms where they first
appear. Prefer concrete addresses, requests, artifacts, and consequences over broad
claims about intelligence or memory.

## Anti-references

- A generic AI landing page built from abstract gradients and unsupported claims.
- A security story conveyed only through color or a decorative architecture image.
- Fake terminals, fabricated metrics, customer logos, or testimonials.
- Copying another ByteDesk product's accent, density, or component system.
