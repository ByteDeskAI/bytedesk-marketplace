# Design — ByteDesk Gateway

Canonical design profile for `bytedesk-remote-gateway`. Read after the
[shared foundation](../../DESIGN.md); the consumer repo's root `DESIGN.md` carries only
local exceptions and enforcement commands.

This profile has three normative companions:

- [`CLIENT_UI.md`](CLIENT_UI.md) — cross-platform shell, adaptive layout, input, AG-UI,
  and parity contract;
- [`COMPONENTS.md`](COMPONENTS.md) — renderer-neutral component anatomy and states;
- [`VISUALIZATIONS.md`](VISUALIZATIONS.md) — operational chart and live-data rules.

## Product stance

**Creative north star: "The Operator Console."**

Gateway is secure remote access to your own workstation — terminal, desktop, files, and
an AI workroom behind real authentication. Its UI is a **single-operator console**, not
a dashboard product: the person using it is already inside the machine and needs the
shortest path between intent and a live session. Visual authority comes from density,
hierarchy, and honest live state, never decoration.

The console covers Sessions (tab launcher plus terminal), Mission Control health, the
Agentic workroom, Files, Security admin, and Infrastructure. Product direction lives in
[`PRODUCT.md`](PRODUCT.md).

Browser and native clients share one semantic interface. They may use platform-native
windowing, menus, dialogs, notifications, credential stores, and file pickers, but the
Gateway workspace keeps the same hierarchy, terminology, component states, shortcuts,
authorization, and consequences.

## Token source

- Family value layer: `tokens/css/bytedesk.css` from this repo, consumed from the
  mounted submodule at `.context/design-system`.
- Canonical machine-readable source: `tokens/bytedesk.tokens.json`.
- Generated native/code adapters:
  `tokens/platforms/typescript/bytedesk-tokens.ts`,
  `tokens/platforms/rust/bytedesk_tokens.rs`, and
  `tokens/platforms/go/bytedesk_tokens.go`. They are generated by
  `node scripts/generate-platform-tokens.mjs` and checked by the repository validator.
- Browser consumer token root: `web/src/styles/theme.css`. Its local aliases (`--bg`,
  `--text`, `--accent`, `--ok`, `--radius`, `--font`, …) **map to** `--bd-*` values;
  the SPA never declares a colour, spacing, size, type, radius, stroke, opacity, chart,
  or motion literal outside that mapping.
- Native consumers map generated values into the toolkit's theme object. Native
  components do not copy values into Rust or Go source by hand.
- Product accent: **Gateway blue**, resolved by `data-bd-product="gateway"` on web and
  the equivalent product-theme selection in native clients. Components read the accent
  role, never the hex.
- Validation: `node scripts/validate.mjs` here; then `npm run build` in Gateway `web/`
  plus `go test ./...` after consumer adoption.
- Foundation value changes land in this repo first (shared `DESIGN.md` §8); the gateway
  then re-pins the submodule.

## Visual language

**Palette roles.** Dark-first from `--bd-bg-base`, stepping through subtle / surface /
elevated / overlay for panels, controls, and hover states. Rules use `--bd-border-*`;
type uses the `--bd-text-*` ramp with a distinct disabled tier for inert chrome.

- **Gateway blue ramp** (`--bd-blue-50`…`--bd-blue-900`, hue `256.13`): identity.
  Canonical action colour is `--bd-blue-500` / `--bd-accent` =
  `oklch(0.5960 0.2028 256.13)`. Roles: `--bd-accent-subtle|muted|default|emphasis|fg`.
  Full-palette: blue is primary; chrome uses the ramp; the terminal canvas stays
  `--bd-bg-base`.
- **Per-desk tint** (`data-bd-desk` on AppShell): hue shift *inside* blue on the
  active rail row and a light mix on the sidebar. Sessions 256, Files 238, Projects
  274, Agentic 264, System 248, Developer 284. Stage fill is never desk-tinted.
- **Brand orange** (`oklch(0.6375 0.2050 38.67)`): wordmark title, Store buy/entitle,
  brand mark ring. Not a second action colour on operator desks.
- **Semantic ok / warn / danger / info**: first-class fills (`--bd-*-bg` / `*-line`)
  on banners, chips, destructive confirms. Always paired with a word. Never a left
  stripe. Guest `/g/{token}` uses info for the jail banner.
- **Charts** use `--bd-chart-*` in the declared order and combine hue with labels,
  markers, line style, direct values, or a data table.

Guest invite is the same palette, **committed mix**: no operator rail, blue-cast
ground, one primary in `--bd-blue-500`. After redeem, thin guest chrome + Files
desk tint.

Dark theme only. A theme engine (`data-bd-theme`) is later work.

**Typography.** IBM Plex Sans (`--bd-font-sans`) for all chrome; IBM Plex Mono
(`--bd-font-mono`) for the surfaces that are genuinely machine text — terminal output,
paths, IDs, IP addresses, commands, log lines. Console text runs at a smaller base than
marketing surfaces; hierarchy comes from weight and colour, not from large type.

**Density.** Operator density is a first-class product decision: 28-unit compact rows
and controls, a 2/4/6/8/12/16/20/24/32/40/48 spacing ladder, a fixed narrow sidebar
and a short top bar. Coarse-pointer clients expand hit targets to 44 units. Chrome must
never cost more vertical space than the work it frames — the terminal and file panes
are the product; everything else is a frame.

**Status vocabulary.** Live state is shown as dot + word (never colour alone), with
relative time in the label and the absolute timestamp available on hover or inspection.
Health that streams over SSE or AG-UI must visibly distinguish *live*, *paused*,
*waiting*, *stale*, *disconnected*, *cancelled*, *failed*, and *complete*. A stale
snapshot presented as current is a correctness bug, not a styling choice.

**Elevation.** Flat by default; depth is tonal (base → subtle → surface → elevated).
Shadows are reserved for genuinely floating layers — overlays, palettes, portaled
panels, and native child surfaces — and never decorate a resting panel.

**Motion.** 120–250ms, `--bd-ease-out-expo`, on hover, focus, tab switch, and panel
open. Never animate layout properties in the session stage; a terminal must not reflow
for aesthetics. Browser and native clients honor reduced motion.

## Component and composition rules

- **App shell**: a short top bar plus adaptive navigation. Wide layouts use the labeled
  sidebar, standard layouts use the icon rail, and compact layouts use a sheet or
  bottom primary navigation. The route order, active desk, counts, and plugin
  provenance remain the same.
- **Sessions stage**: the terminal or remote surface fills the stage; tab strip and
  launcher controls sit in the chrome, not over the stage. Overlays that cover a live
  session are dismissible by keyboard and never trap focus.
- **Tables** (sessions, viewers, bans, audit): dense rows, hairline dividers, muted
  uppercase micro-labels, mono for machine values, numerics right-aligned. Empty states
  are one muted sentence inside the table body — no illustrations.
- **Destructive actions** (kick, ban, revoke): inline two-step confirm in place; the
  affected identifier and consequence are restated in the confirm step. No modal-first
  patterns.
- **Security posture surfaces**: the console states its own limitations plainly — a
  warn-toned banner with a full 1px border, never a side stripe, never dismissed by
  default. Fake enterprise RBAC chrome is prohibited.
- **Secrets in flight** (enroll tokens, install credentials): shown once in a sunken
  mono reveal block with an explicit copy affordance and a "shown once" label.
- **Forms**: sunken input wells, 1px borders, accent focus ring, server-side validation
  mirrored in the UI — the UI may disable an invalid choice, but never *only* the UI.
- **Agent surfaces**: AG-UI messages, tools, approvals, steps, state, and errors use the
  same component contract regardless of provider. Provider accent identifies identity,
  not status.
- **Embedded surfaces**: xterm, noVNC, Monaco, browser sessions, and plugin WebViews are
  framed by ByteDesk chrome that owns title, permission, freshness, focus, escape,
  reconnect, and fullscreen behavior.

## Accessibility

Shared WCAG 2.2 AA foundation applies. Gateway-specific requirements:

- Every action reachable from the console must be reachable by keyboard, including tab
  switching, the launcher, command palette, approvals, and overlay dismissal. Focus is
  always visible against the dark ground.
- Terminal and remote-screen surfaces are third-party render targets; the surrounding
  chrome therefore carries the accessible labels, state announcements, and keyboard
  escape route the embedded surface cannot provide.
- The compact client's on-screen key row is an accessibility feature, not a nicety: it
  is the only way to send modifier keys on touch devices and remains reachable.
- Live-updating health and AG-UI regions announce politely; they do not announce every
  sample, token, or terminal byte.
- Charts include a table or ordered values, keyboard inspection, and non-colour series
  distinction.
- Native clients respect operating-system text scale, reduced motion, contrast, and
  coarse-pointer preferences where available.

## Exceptions to the shared foundation

- **Console density.** Gateway runs tighter than the family default because it frames a
  terminal. The density ladder above is expressed in canonical tokens and mapped by
  each client adapter, not as per-component literals.
- **Embedded third-party surfaces.** Terminal, editor, plugin, and screen-mirror
  renderers are not token-styled ByteDesk components. They are configured to the
  nearest token values and are explicitly out of scope for component internals; their
  ByteDesk frames remain in scope.
- **Platform-native integration.** Operating-system menus, title bars, dialogs,
  notifications, credential stores, and tray surfaces may follow platform conventions.
  Their command identifiers, labels, authorization, and resulting Gateway state remain
  consistent with the browser client.

## Generated art

The family contract is [`DESIGN.md` §10](../../DESIGN.md) — read it first. It holds the
invariants: unlifted dark ground, exactly one lit element, accent as edge-light or
contained glow and never a fill, matte with fine grain, composition that breathes, and
the hard limit that generated art carries no logos, copy, controls, invented metrics,
functional icons, or rasterized UI.

This section supplies the half that must not be shared.

**Motif — Many rooms reached from one place.**

Gateway hands a developer remote workspaces. Apertures cut into deep dark at different depths, each lit from within, one nearer and brighter than the rest.

**Accent:** product.gateway blue, read live from `tokens/`. Never sampled from a rendered image.

**Watch for:** The lit interiors are easy to over-bloom until the frame is more light than dark. The dark is the subject; the openings are the exception.

A piece that would work equally well for another ByteDesk product has failed this
section, however good it looks.
